Architecture

Connect without opening a single port

The relay bridges your laptop to the instance over outbound-only WebSocket connections. Neither side needs an inbound firewall rule or a public IP.

Your laptop Relay server Cloud instance ───────────────────────────────────────────────────────────────────────────── runlease up → register token ─────────────────────────→ ← token registered [instance boots] runlease-agent starts ←── outbound WS connect ── ← token matched runlease connect → join token ───────────────────────────→ ← connected ══════════════════════════════ SSH over WebSocket ══════════════════════════ The relay sees only encrypted ciphertext. It cannot authenticate as you or impersonate the instance.
🔑

Token-based slot matching

The CLI pre-registers a random token before the instance boots. The agent claims it on startup. The relay only brokers the connection — it never stores credentials or session keys.

♻️

Reconnectable sessions

After a session ends, the relay holds the slot open. The agent automatically reconnects within 5 seconds. runlease connect works again immediately — no re-launch needed.

⏱️

TTL self-termination

Set a TTL and the instance deletes itself via the cloud metadata API. No daemon needed on your laptop. No forgotten instances. The terminate script is installed at boot and runs with no internet access to your credentials.

🌐

Multi-cloud

AWS spot instances and GCP preemptible VMs with a single CLI. AMI auto-detected on AWS. Abstract instance classes (compute.small, compute.large) translate to provider-specific types automatically.

Security model

Hardened at every layer

runlease was designed so that compromising any single component yields an attacker nothing useful. The relay, the instance, and the credentials are all independently protected.

Zero-knowledge relay

The relay is a dumb pipe. It never sees SSH private keys, host keys, or session data. All authentication and encryption happens inside the SSH layer — the relay only forwards ciphertext.

Pre-generated host keys

The SSH host key pair is generated by the CLI before the instance launches. The private key is injected via userdata; the public key is stored locally. Your SSH client verifies identity before the first byte is sent — no trust-on-first-use window.

Ephemeral credentials

A fresh ed25519 keypair is created for every instance launch. The private key is stored encrypted with AES-256-GCM under a master key on your machine. Credentials are wiped on runlease down.

sshd hardening

The startup script appends a hardening block to sshd_config at boot: password auth disabled, only pubkey accepted, root login denied, AllowUsers runlease-agent, max 3 auth attempts.

No credentials on instance

Self-termination uses the cloud metadata API (GCP service account token, AWS instance-initiated shutdown behavior). Your cloud credentials never leave your laptop — they are not embedded in userdata or passed to the relay.

Restricted host keys

Auto-generated RSA/ECDSA/DSA host keys are deleted at boot. Only the pre-generated ed25519 key is kept. The client uses FixedHostKey — any unexpected key from the server causes an immediate connection abort.

Threat scenario Impact
Relay server fully compromised Cannot SSH in — no client key. Cannot impersonate instance — no host key. Cannot decrypt traffic — keys derived per-session via ECDH inside SSH.
Relay token intercepted in transit Token alone doesn't grant access. The instance still requires your client key (stored encrypted on your laptop). The relay checks Google ID token auth on registration.
Attacker-controlled MITM between client and relay SSH host key is pinned using FixedHostKey. Any key substitution causes connection failure before authentication.
Abandoned running instance (forgot to terminate) TTL self-termination deletes the instance via cloud API. No external ping-home needed — the instance acts autonomously using its own metadata credentials.
Master key file stolen from laptop Attacker can decrypt stored instance credentials — but each credential is per-instance and short-lived. Rotate by running runlease down.
Configuration

Full manifest reference

For quick launches use runlease up --flags or runlease configure. For repeatable setups, commit a manifest YAML. Generate one interactively with runlease manifest init.

manifest.yaml
# ── identity ──────────────────────────────────────────────────────
name: my-worker          # used as the instance display name and tag
provider: aws           # aws | gcp
region: us-east-1

# ── instance type ─────────────────────────────────────────────────
instanceType: g4dn.xlarge   # exact provider type, OR use instanceClass
# instanceClass: compute.gpu  # abstract: compute.small / .medium / .large / .gpu

# ── image ─────────────────────────────────────────────────────────
# aws:   leave blank → auto-detected (latest Amazon Linux 2023 for the region)
# gcp:   required, e.g. debian-cloud/debian-12
baseImage: ""

# ── networking ────────────────────────────────────────────────────
publicIp: true    # default: true (direct SSH). false → relay mode, no public IP

# AWS networking (optional — defaults to default VPC)
securityGroupIDs:
  - sg-0123456789abcdef0
subnetID: subnet-0123456789abcdef0
instanceProfile: arn:aws:iam::123456789012:instance-profile/MyProfile
                    # gives instance IAM credentials (e.g. for SSM, S3 access)

# GCP networking (optional)
networkTags:
  - allow-ssh
  - http-server
serviceAccount: worker@project.iam.gserviceaccount.com
                    # enables GCP APIs and IAP tunnels on the instance

# ── relay ─────────────────────────────────────────────────────────
relay:
  addr: wss://relay.example.com
        # when set: runlease-agent installed on boot; connect with 'runlease connect'
        # supports: host:port  ws://...  wss://...

# ── auto-termination ──────────────────────────────────────────────
reclaim:
  ttl: 4h   # instance self-terminates after this duration
            # GCP: calls Compute API via metadata service token
            # AWS: systemctl --force --force poweroff (InstanceInitiatedShutdownBehavior=terminate)
            # no daemon needed; uses systemd-run --on-active=<seconds>

# ── tags / labels ─────────────────────────────────────────────────
tags:
  team: ml-infra
  project: gpu-experiments
  # runlease-managed, runlease-created-by, runlease-expires-at
  # are added automatically; your tags override on conflict
⚡

Quick launch flags

All manifest fields have CLI flag equivalents for ad-hoc launches:

$ runlease up \
    --provider aws \
    --region eu-west-1 \
    --size compute.medium \
    --ttl 2h \
    --relay wss://relay.example.com
🛑

Termination options

Three ways to terminate an instance:

# from your laptop
$ runlease down

# from inside the instance
$ runlease-terminate

# automatically after TTL
reclaim:
  ttl: 4h
CLI reference

Every command

All instance-targeting commands auto-select when one instance is running, and show a pick-list when multiple are.

runlease configure Interactive setup wizard — provider, region, size, TTL, relay. Saves defaults to ~/.runlease/config.yaml.
runlease config show Print current configuration.
runlease config set <key> <val> Set a single config value by dot-notation key (e.g. relay.addr, defaults.ttl).
runlease up Launch a spot instance from flags, config defaults, or -m manifest.yaml. Waits for SSH/relay readiness and drops you into a shell.
runlease connect [name] SSH into a running instance through the relay. No public IP needed. Auto-reregisters if relay was restarted.
runlease ssh [name] Direct SSH using the instance's public IP (no relay).
runlease iap [name] SSH via GCP Identity-Aware Proxy. Requires gcloud and roles/iap.tunnelResourceAccessor.
runlease ssm [name] AWS SSM Session Manager session. Requires instance profile with AmazonSSMManagedInstanceCore.
runlease down [name] Terminate an instance and delete its credentials. Prompts for confirmation; skip with -y.
runlease list Show all tracked instances with provider, IP, region, age, and time until expiry. Filter with --label key=value.
runlease manifest init Interactive wizard that generates a manifest YAML with provider-specific hints and all advanced fields.
runlease catalog List available abstract instance classes per provider with their mapped instance types.
