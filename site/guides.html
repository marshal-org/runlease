Guides

Guides to giving a coding agent a machine

Short, practical pages on the jobs Runlease is used for. Each one stands alone.

CLAUDE CODE

A sandbox for Claude Code

Give Claude Code a separate Linux machine to build, test and run untrusted code on: a spot VM in your own AWS or Google Cloud account that deletes itself.

COST

Spot VMs for coding agents

How to run AI coding agents on spot instances in your own AWS or Google Cloud account: what spot saves, what it can take away, and how a lease keeps the bill bounded.

MCP

An MCP server for cloud machines

runlease mcp is a Model Context Protocol server: typed tools that let any coding agent launch a spot VM in your cloud, run commands on it, copy files and delete it.

TEMPORARY MACHINES

Cloud VMs that delete themselves

Launch a temporary Linux VM in your own AWS or Google Cloud account with one command. It has no public address and deletes itself when its lease ends.

CHOOSING

Hosted sandbox, or your own cloud?

When an AI coding agent needs somewhere to run code, you can rent a hosted sandbox or use a VM in your own cloud account. What each is good at, and how to choose.

Running agents for a whole team? Runlease gives one agent one machine. Marshal, from the same team, runs AI coding agents in isolated pods inside your own VPC, with credential isolation, audited egress and live tool policies.

Tuning the whole delivery line? A machine per agent is one part of it. Lights Out, a simulator of a software delivery line with AI coding agents, lets you find where work piles up on a ten-engineer team, or on your own team's numbers. It is free, and it is part of The Software Factory, a community guide started by the founder of Runlease.
