Install

One verified binary, in your home directory.

The installer downloads the release for your machine, checks its SHA-256, and puts runlease in ~/.local/bin. No sudo, no package manager, no background service.

Before launch: public releases are not published yet, so the commands on this page will report that no release was found. They start working when the repository opens.

Install

$ curl -fsSL https://runlease.online/install.sh | sh

Works on Linux and macOS, on Intel and Arm. If you would rather read a script before running it, which is a good habit for a tool that holds SSH keys:

$ curl -fsSL https://runlease.online/install.sh -o install.sh
$ less install.sh
$ sh install.sh

What the script does

  1. 01

    Works out your operating system and CPU.

  2. 02

    Downloads that binary and checksums.txt from the GitHub release.

  3. 03

    Checks the binary's SHA-256 against checksums.txt, and stops without installing on a mismatch.

  4. 04

    If cosign is installed, also checks the signature on checksums.txt.

  5. 05

    Copies the binary to ~/.local/bin/runlease. Nothing else on your system changes.

RUNLEASE_VERSIONlatestA specific release, for example v0.5.0

Install by hand

The script is a convenience. These are the same steps, and they are the way to install on Windows.

# pick the latest release, and your platform
$ VERSION=v0.5.0
$ OS=linux ARCH=amd64      # or darwin / arm64
$ BASE=https://github.com/marshal-org/runlease/releases/download/$VERSION

$ curl -fsSLO $BASE/runlease-$OS-$ARCH
$ curl -fsSLO $BASE/checksums.txt
$ sha256sum --check --ignore-missing checksums.txt
$ install -m 0755 runlease-$OS-$ARCH ~/.local/bin/runlease

To also check the signature and the build provenance, see verify a release.

Why not go install?

You can build from source, and it works. It is not the recommended way to install, for a security reason.

A release build of the CLI has the SHA-256 of its matching agent compiled in. Every VM you launch checks the agent it downloads from the relay against that value before running it. A binary from go install has no such value, so that check is off, and the CLI warns you at every up.

# Go 1.26 or newer. Fine for development, and against a relay you run yourself.
$ go install github.com/marshal-org/runlease/cmd/runlease@latest

If you do use a source build against a relay you do not run, pin the agent's digest in each manifest with relay.agentSha256. How agent verification works.

First launch

You need credentials for one cloud. Runlease uses the ones your cloud's own tools use, and stores none of its own.

Google Cloud

$ gcloud auth application-default login
$ gcloud config set project MY_PROJECT

AWS

The usual credential chain: environment variables, a profile, or SSO.

$ aws sso login

Then choose a relay. The quickest start is the free public one:

$ runlease config set relay.addr wss://connect.runlease.online
$ runlease login                 # approve a short code in any browser

$ runlease configure             # provider, region, default size and lease
$ runlease up                    # launch with your defaults
$ runlease exec NAME -- uname -a # run something on it
$ runlease down NAME --yes       # or let the lease delete it

Your subnet needs a way out. A machine launched through a relay gets no public address, so it reaches the relay through your subnet's NAT gateway. runlease up checks for one and tells you before it creates anything. If you have none, add --public-ip: the address carries outbound traffic only, and SSH still listens on localhost.

The machine is yours. It runs in your cloud account, on your bill. The relay only connects you to it. What the public relay allows, and how to run your own.

Uninstall

$ rm ~/.local/bin/runlease
$ rm -r ~/.runlease              # saved keys, settings and sign-in

Run runlease list first and take down anything still running, because the second command deletes the keys you would need to reach it. The machines still delete themselves when their leases end.
